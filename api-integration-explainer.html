Protokol Komunikasi
Tiga protokol yang digunakan untuk menghubungkan setiap layer dalam sistem
REST

REST API

PRIMARY

Komunikasi utama antara seluruh layer. Menggunakan JSON payload dengan autentikasi session cookie untuk dashboard dan API key untuk perangkat IoT.

Digunakan untuk: Data ingestion, actuator control, dashboard data, device management, konfigurasi threshold, autentikasi user
WS

WebSocket

REAL-TIME

Pusher WebSocket untuk broadcast event sensor ke semua client yang terkoneksi. Memungkinkan update real-time tanpa menunggu polling interval.

Digunakan untuk: SensorDataReceived event dari Laravel ke React dashboard via Laravel Echo — update instan di semua client
SER

USB Serial

HARDWARE

Komunikasi antara ESP32 dan Python Serial Bridge via USB. JSON payload setiap 3 detik untuk data sensor, dan command response untuk aktuator.

Digunakan untuk: Sensor reading dari ESP32 ke Serial Bridge, Command dari Bridge ke ESP32, ACK response setelah eksekusi
3
Alur Pertukaran Data
Dua alur utama: upstream (sensor ke dashboard) dan downstream (dashboard ke hardware)
U
Sensor ke Dashboard (Upstream)
1
ESP32 Membaca Sensor
MQ-2, DHT22, KY-026 dibaca setiap loop, dikirim sebagai JSON via Serial USB
{"gas_value":350,"temperature":28.5,"flame_value":800}
2
Serial Bridge ke API
Python serial_bridge.py menerima JSON, forward ke Laravel via HTTP POST dengan API key
POST /api/ingest — Header: x-api-key
3
Fuzzy Logic Engine
27 Sugeno rules difuzzifikasi: triangular membership, weighted average, menghasilkan skor 0-100
score=59.3 -> MEDIUM -> fan=60% buzzer=OFF
4
Simpan dan Broadcast
Data disimpan ke MySQL, activity log dicatat, event di-broadcast via Pusher ke semua client
SensorDataReceived -> Laravel Echo -> React setState
D
Dashboard ke Hardware (Downstream)
1
User Mengklik Aksi
Admin menekan tombol di dashboard React: Aktifkan Fan, Stop Buzzer, atau Emergency
POST /api/actuator {"target":"exhaust_fan","action":"START"}
2
Command Queue
Laravel menyimpan command ke tabel commands (status: pending) dan mengaktifkan mode manual
Command::create — status: pending, mode: manual
3
Bridge Polling
Python worker poll GET /api/command/get setiap 2 detik, mengambil command dengan atomic lock
GET /api/command/get -> lockForUpdate -> processing
4
ESP32 Mengeksekusi
ESP32 menerima command via Serial, mengatur PWM fan atau GPIO buzzer, mengirim ACK
{"type":"ack","id":42,"status":"completed"}

Akses Remote & Multi-Client
Kemampuan sistem dalam melayani banyak client dan perangkat secara bersamaan
RC

Akses Remote

Dashboard dapat diakses dari mana saja melalui browser. Tidak perlu berada di jaringan lokal yang sama dengan ESP32.
  • Session-based auth — cukup login sekali, session aktif di browser
  • Responsive UI — desktop dan mobile didukung
  • Real-time updates — data sensor terbaru tanpa refresh manual
  • HTTPS ready — deploy di VPS dengan SSL untuk akses aman
MC

Multi-Client

Banyak admin dapat login dan memantau dashboard secara bersamaan tanpa konflik.
  • Stateless API — setiap request independen, tidak terikat session tunggal
  • WebSocket broadcast — semua client menerima update yang sama
  • Shared database — single source of truth di MySQL
  • Configurable polling — setiap client bisa set interval berbeda
MD

Multi-Device

Sistem mendukung registrasi beberapa ESP32 di lokasi berbeda, masing-masing dengan API key unik.
  • Device registry — CRUD perangkat via API atau dashboard
  • Per-device isolation — data sensor, command, dan log terpisah per device_id
  • Room selection — dashboard bisa switch antar device/lokasi
  • API key per device — autentikasi terisolasi, revoke tanpa ganggu device lain
BT

Backend Reliability

Backend Laravel dirancang untuk operasi 24/7 dengan penanganan error dan data integrity.
  • Atomic commands — SELECT ... FOR UPDATE mencegah race condition
  • Transaction safety — sensor data dan log disimpan dalam satu transaksi
  • Auto-recovery — mode manual auto-switch ke auto setelah 30s inaktivitas
  • Worker heartbeat — monitoring status ESP32, deteksi offline otomatis

Status: Cukup, Tetapi Bisa Diperkuat
Mekanisme dasar sudah berjalan (API Key, Session Auth, Middleware), namun validasi input dan hak akses granular belum diimplementasikan secara rinci.
✓
Sudah Diimplementasi
API Key Authentication
Setiap device ESP32 punya API key unik. Request tanpa key yang valid ditolak 401.
Header: x-api-key: key-warehouse-001
Check: DB::table('devices')->where('api_key', $key)->exists()
Session Authentication
Dashboard menggunakan Laravel session cookie. User login via /api/login, session tersimpan di server.
Cookie: laravel_session, XSRF-TOKEN
Check: session()->get('user_id')
Middleware CheckApiKey
Middleware memeriksa API key untuk rute IoT. Jika ada session cookie (frontend), skip API key check.
Route::middleware([CheckApiKey::class])->group(...)
Atomic Command Polling
SELECT ... FOR UPDATE mencegah dua worker mengambil command yang sama secara bersamaan.
Command::lockForUpdate()->first()
!
